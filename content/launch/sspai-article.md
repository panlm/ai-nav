**标题：** 我为什么觉得现有 AI 工具导航站都不好用，以及我做了什么

**利益相关声明：** 作者是该项目开发者

## AI 工具过载时代的选择焦虑

2026 年初，我想找一个 AI 视频生成工具。

打开 Google，前三个结果分别是「2026 年最好的 18 个 AI 视频工具」「Top 10 AI Video Generators Compared」和「AI 视频工具大全（收录 200+）」。我点进去，三篇文章的推荐列表有 80% 重合，都把 Runway 排第一、Sora 排第二，但没有一篇告诉我：**以我的预算和需求（做一个 60 秒产品 Demo），到底该用哪个？**

这就是现有 AI 工具导航站的核心问题：**它们在做目录，不在做导航。**

## 扒一扒主流导航站的问题

在做自己的项目之前，我认真用了一个月的主流 AI 工具导航站。以下是我的真实体验：

### Futurepedia：量大但过时
Futurepedia 收录了超过 5000 个 AI 工具，是目前最大的导航站之一。问题是——很多工具页面的信息还停留在一两年前。我点进去 3 个「推荐」工具，1 个已经关停，1 个转型了完全不同的方向，只有 1 个还在正常运营。

它的分类也过于粗放——「Writing」这个分类下有 400+ 个工具，从 ChatGPT 到某个只能写 haiku 的小众工具混在一起，筛选形同虚设。

### There's an AI for That：搜索是亮点，但体验粗糙
TAAFT 的搜索功能确实比其他导航站好——你可以用自然语言描述需求，它会匹配工具。但搜索结果页面信息量太少，基本只有一句话简介和一个链接，还是要自己点进去逐个了解。

它的盈利模式是收费排名（Sponsored），这意味着搜索结果的前几名不一定是最适合你的。

### 国内导航站：SEO 优化 > 用户体验
国内的 AI 导航站（不点名了）普遍存在一个问题：内容是为搜索引擎写的，不是为用户写的。页面上堆满了关键词，工具简介像是机翻的，更新频率参差不齐。

### 共性问题总结

| 问题 | 表现 |
|------|------|
| 信息过时 | 大量已关停/转型的工具仍在推荐位 |
| 分类粗暴 | "写作"分类下 400 个工具，无法进一步细分 |
| 缺乏对比 | 只有单独介绍页，没有横向比较 |
| 信任缺失 | 付费排名和 AI 生成的虚假评测混杂 |
| 无场景匹配 | 按工具分类，不按用户实际需求分类 |

## 我的解决思路

基于以上痛点，我开始做一个自己想用的 AI 工具导航站。设计原则很简单：**从用户场景出发，不从工具出发。**

### 1. 场景驱动的分类体系

传统导航站的分类是「工具能干什么」——写作、图片、视频。我的分类是「用户要干什么」——做产品 Demo 视频、运营小红书、从 0 开发一个 SaaS。

每个场景不只推荐单个工具，而是给出**完整的工具组合方案**。比如「用 AI 从 0 做产品 Demo 视频」这个场景，我的推荐是：

> Claude 写脚本 → ElevenLabs 配音 → Screen Studio 录屏 → CapCut 剪辑

用户不需要自己从 200 个视频工具里挑选和组合，我帮你做了这一步。

当然，基础的按功能分类也保留了——8 大分类、40+ 二级分类，作为浏览入口。两种导航方式共存。

### 2. 工具生死状态追踪

这是我最想做的功能。每个工具页面标注运营状态：

- 🟢 **活跃** — 近 3 个月有更新
- 🟡 **停更** — 超过 3 个月无更新
- 🔴 **已关停** — 确认停止服务

配合每周发布的「AI 工具周报」，追踪本周新上线和关停的工具。这解决了现有导航站最大的信任问题——**你推荐的工具，现在还能用吗？**

### 3. 横向筛选维度

除了分类，全站支持多维度筛选：

- **定价：** 免费 / 免费增值 / 付费 / 企业级
- **中文支持：** 原生中文 / 支持中文 / 仅英文
- **类型：** 开源 / 闭源 / API
- **平台：** Web / Mac / Windows / iOS / Android / Chrome 插件

作为一个中文优先的导航站，「中文支持程度」这个维度特别重要。很多工具标榜"支持多语言"，但中文体验和英文差距巨大。我会如实标注。

## 技术实现

简单说一下技术选型：

- **框架：** Astro 5 — 纯静态为主，性能好，SEO 友好
- **数据管理：** 飞书多维表格 — 非技术团队成员也能编辑工具数据
- **部署：** Vercel — 零运维
- **路由：** `/category/{primary}/{secondary}` + query params 做筛选

选 Astro 而不是 Next.js 的原因：导航站的内容以静态为主，不需要复杂的客户端交互，Astro 的 Island Architecture 让页面几乎零 JS 开销。

## 目前的状态和不足

站点已上线（[ai-nav-liart.vercel.app](https://ai-nav-liart.vercel.app)），目前收录了 50+ 精选工具。坦诚说几个不足：

- **工具数量有限** — 追求精选，但覆盖度还不够。计划每周新增 10-15 个
- **场景方案内容还在建设中** — 目前完成了 5 篇，计划持续产出
- **缺少用户评论系统** — 目前评分是编辑评分，后续会开放用户评价
- **没有 API** — 暂时不提供数据接口
